## 唯一编辑正本

每区只维护 `整区/档案/{行政区代码}/工作/行政区主档.md`；同目录 `辅助记录.md` 保存其它对象的唯一去向、证据、待判和覆盖。有效对象不在两份文件中重复登记。

本仓库直接使用维护者原工程中的这些文件，没有搬迁或另建可编辑副本。GitHub 是同一套文件的协作版本；备份、历史回货和自动生成的 JSON 是恢复或派生材料，不独立编辑。发生不同修改时合并回这里，不建立“备用正本”。

## 协作与发布

① 先与维护者确认负责的行政区或对象，在工作分支修改正本，保留原 ID、表头、来源字段和其它人的修改。大文件建议取得仓库后用文本编辑器修改；若网页不支持编辑，不拆成第二套资料。

② 提交更改说明和依据，由维护者在现有完整工程中核对、接收。合并协作修改不等于发布给酒馆。

③ 维护者准备具体资料更新清单，**每次先询问项目所有者，获得明确批准后才发布**。本仓库没有自动发布流程，也没有本体仓库的发布凭据。详见 [发布规则](RELEASE_POLICY.md)。

## 来源与核验边界

新地点只承接 Overture `2026-10-21.0`，不引入旧点库、旧正文库或旧站网。规则见 [总规则](流程/总规则.md)、[唯一主档合同](流程/唯一主档合同.md)、[字段参考](流程/字段参考.md)和[分类目录](共用/分类树与标签目录.md)。共享规则保持本轮原有版本，不能自行改规则或指纹。

完整原始分片、只读 baseline、证据附件、中央调度和编译工具保留在维护者原工程；没有随这个仓库全部交付。引用中的 `.local`、`.baseline` 或来源文件名是追溯入口，不表示文件已公开可下载。本仓库可供地点资料协作，**不宣称单独克隆后能完成整区重建或酒馆发布**。

公开文件把维护者工程绝对路径表示为明确占位符；本机 Git 取回时可还原原值，原位主档字节和既有验收指纹保持。占位符不是网址，也不是可编辑的地点内容；机制见 [路径说明](tools/README.md)。

[来源与许可](ATTRIBUTION.md)随资料保留。资料接收、文件核验、真实 SillyTavern 和用户实测分别记录，不互相代替。
