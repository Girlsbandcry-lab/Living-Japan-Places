# 每区唯一 Markdown 主档合同

## 1. 唯一权威

每区只持续维护一份 `行政区主档.md`，位于 `工程表/行政区重建/整区/档案/{行政区代码}/工作/`。

同目录 `辅助记录.md` 承接其指定辅助表，`.baseline/` 为只读输入底表。中央回货中的 `authoring/` 保存当次受审原文，不作为另一份可编辑主档。

已审状态以受审版本判断。工作主档新增内容须重新生成并接收，不能沿用旧审收结论。

| 材料 | 权威边界 |
|---|---|
| 行政区主档 | 当前有效对象、位置、分类、直接成员边、已接受关系和任务。 |
| 辅助记录 | 排除、归并、待判及退役等其它唯一去向，以及证据、名称、覆盖和解释。 |
| 原始 Overture | 完整只读原值及源行追溯。 |
| 机器底表 | 全量输入展开及只读机器预填，不表示已完成判断。 |
| 自动十表、索引、统计 | 可重建派生结果，不手工独立维护。 |
| 共用规则与分类合同 | 所有区共用的判断规则和词典，不是另一份地点档案。 |

发现派生结果错误，修正主档或负责派生的程序，再重建。不能只改 JSON 后宣称主档已完成。

## 2. 主档四部分

### 元信息

记录行政区、owner、来源版本、领取版本、共同规则和分类引用。

由初始化工具给出固定键。负责人不手工改来源指纹来绕过版本检查。

### 地点

每个对象只出现一次，用稳定 ID 识别。

主档 objects 放保留源对象和已接受结构父；辅助 dispositions 放其它状态。同一 ID 只在一处，状态变化时移动整行。

片区用现有 area 记录，不增加第二套片区表或外部来源 POI。结构片区可暂空用途分类，有值时校验有效性；名称与位置记录说明大体位置及采用方式。可用小片建立后按写作关联就近吸纳，主动减少同级堆点，不要求逐点官方精确归属。同一源点保持唯一，合理工程名称自然使用且不过多堆名；既有设施内部链继续复用，外围小片组织按总规则第 5、6 节保存。

初始 keep 候选仍可能未分拣，源对象实际完成看 coverage；区级片区工作看 area_partition 任务。分组标题只方便阅读，不暗含父子关系。

表格可以分段重复表头，但不能在树的每一层重复同一对象。

### 关系

直接父只记在成员关系表中。程序再生成来源归属与区域父链，不另手填第二套 parentIds。祖先和全部后代沿图读取，不人工补重复祖先边。

related 仅记录实际非包含关联。同体、归并、包含必须分清。

### 任务

任务使用稳定任务 ID。记录范围、负责人、状态、结果和下一动作。

对象通过任务 ID 关联工作，避免在多张表反复复制一整份地点清单。

源对象分拣用 sorting，区负责人切片、框架维护与归挂汇总用 area_partition，后期下潜另记主题。task-objects 关联实际源对象或 area 对象，结果引用同区主档与辅助证据；未形成对象的片区线索保留辅助记录。旧精选名字只是后期线索，不能直接产生采用地点或已完成任务。

## 3. 固定字段与开放备注

固定字段保存需要批处理的决定。详细列名、枚举和空值规则见 `字段参考.md`。

开放备注只解释事实或提供线索。分类、父对象、采用位置和任务状态不能只写在备注中。

使用工具生成的表头，不自行改列名、交换语义或拆成自由段落。

表格单元格中的竖线和换行按程序约定编码。长引文放辅助记录，不塞进地点表。

未知、不适用和未处理须明确区分，不能用同一空白含糊代替。

## 4. 辅助记录

同区使用一份结构化 `辅助记录.md`，按程序固定表分段。其它对象去向只存其中 dispositions，不复制有效对象清单。

| 内容 | 保存要求 |
|---|---|
| 来源证据 | 原始出处、版本、原字段或实读材料定位。 |
| 待判 | 关联对象、冲突或缺口、下一动作。 |
| 处置 | 采用／未采用的判断理由及主档回写位置。 |
| 长材料 | 保留必要摘录；已保存原件以引用定位，避免重复拷贝。 |

结构化处置表决定对应对象的排除、归并或待判去向；其余补充字段按合同承接。有效对象及已接受关系进入主档。

散文备注不能另行改变保留资格、分类或归属。改判断须更新相应固定字段，状态变化时移动记录。

异名只记录原写法与证据。辅助处置状态不代表异名已经采用或可激活。

## 5. 小批处理和覆盖

区负责人先集中核对现成划分依据，建立可用框架并登记片区任务。给各子批同版框架，收回新线索统一合并，不要求框架在开批前达到全区零待判。

每个子 Agent 默认每批 50 个对象；复杂批次由区 AI 自行缩小。

1. 领取明确任务、对象范围和本批共同片区框架。
2. 判断保留与用途，再打标签并按真实直接父归挂。
3. 保存本批主档结果及辅助待判项。
4. 区负责人合并保存后，自动领取下一批，不逐批等人确认。

脚本全区底表、自动预分类及复制原行不算处理完成。小批不是抽样，全区输入最终全部有去向。

排除或归并也属于处理结果，必须保留原行和依据。明确待判可完成本批处置，但不能声称地点事实已经确认。

source coverage 与 area_partition 任务分别保存，不用源覆盖完整替代片区建立、归挂和跨批合并结果。结构片区不计入 Overture 输入分母；不设固定片区数、全标签或零待判门槛。

## 6. 单一审收

各区使用同版 Skill、总规则、字段合同、分类和来源。

中央 6astra 统一口径、共用参考和跨区协调，动态派发并有限审收。每个独立区聊天由 6.1sol 负责整区切片与归挂，可用 3 个子 Agent 并行小批。

批次领取避免对象重叠。区负责人统一合并本区主档；跨区实体只有一个 owner，其它区引用。

中央按实际容量安排 2—3 个或更多区并决定推理强度，不固定并发，不混算区聊天与子 Agent 槽位。

最终由同一中央主审审收。自动收货仅形成候选，用户与中央共同判断后才启用。中央核领取版本，再按实际对象变化合并；旧整份回货不能覆盖较新结果。

只退点名问题，已通过部分保留。检查次数限定在本批功能和真实异常，不引入五源六审。

## 7. 程序入口

| 入口 | 职责 |
|---|---|
| district_archive.py init | 从正式全量输入建立主档及辅助记录。已有工作稿不覆盖重做。 |
| district_archive.py next-batch | 只查看下一批，不领取、不记完成。 |
| district_archive.py claim-batch | 领取互不重叠的源对象子批，默认每个子 Agent 50 个对象；片区任务由区负责人维护。 |
| district_archive.py finish-batch | 保存并核实源对象实际覆盖后结束本批，随后自动续批；不自动完成片区任务。 |
| district_archive.py build | 读取主档，生成十表及所需派生内容。 |
| district_archive.py check | 核字段、版本、覆盖、ID、分类和父链等结构。 |

精确参数以同版程序帮助和字段参考为准。程序不得凭表格生成就宣布人工判断完成。

文件结构通过不表示地点事实已全部确认，更不表示已在运行界面或 SillyTavern 使用。

## 8. 共享与恢复

共享文档、程序和引用采用仓库相对路径。本机离线资料位置由实际环境配置。

GitHub 不上传离线大包、本机路径、缓存、运行个人文件；上传前核具体确认范围。

每轮实质修改前留可恢复快照。历史主档与原回货保留；恢复前保存后续修改，不强制重置。
